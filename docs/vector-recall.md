# 向量兜底：召回诊断与结论

对应 issue #20。本文记录实测数字与一个比数字更重要的结论：**现有金标准集结构上无法度量向量兜底**。

## 一、召回层修好了

诊断命令：`idr recall --variants raw,configured --lexical --top-k 100`
口径：48 道可答题，题目绑定的期望证据是否进入向量 top-k。

| 查询形态 | recall@20 | recall@50 | recall@100 |
|---|---|---|---|
| 原始问句（基线） | 19/48 = 39.6% | 22/48 = 45.8% | 25/48 = 52.1% |
| 生产配置（检索指令 + 词面 RRF） | **30/48 = 62.5%** | 38/48 = 79.2% | **44/48 = 91.7%** |

配置含义见 `src/rotating/config/retrieval.yaml`：

- `query_instruction: crosslingual` —— Qwen3-Embedding 的检索指令预设，只作用于查询侧，**不重新嵌入已存向量**；
- `lexical_recall: true` —— 概念名/别名对证据原文做子串匹配，与向量名次用 RRF 融合；
- `query_enrichment: false` —— 曾把概念规范名、别名、概念 ID 的英文词追加进查询。它提升了 @50/@100，但**拖低了 @20**（21/48 → 与指令叠加后 25/48），故关闭。

## 二、但端到端指标没有任何变化

用生产配置跑完整评测（`idr eval`，50 题）：

| 指标 | 改前 | 改后 |
|---|---|---|
| 检索命中率 | 46/48 = 95.8% | 46/48 = 95.8% |
| 引用准确率 | 786/786 = 100% | 100% |
| 拒答正确率 | 50/50 = 100% | 50/50 = 100% |
| 路径分布 | graph 48 / refusal 2 | graph 48 / refusal 2 |

**向量兜底仍然是 0 次命中。**

## 三、为什么：金标准集度量不了向量兜底

`ask` 的检索顺序是图优先、图拒答才走向量。而 48 道可答题**全部由图路径答出**，向量路径根本没有被触发过；唯一走进兜底分支的是两道拒答对照题（R-01、R-02），而它们本来就该拒答。

所以「recall@20 从 19 涨到 30」是真的，但它测的是一个**假设性问题**（「如果走向量，能不能召回到」），不是真实收益。要让向量兜底产生价值，需要一类现在金标准里**不存在**的问题：

- 图里没有对应概念节点、但文献里有答案的口语化问法；
- 只能靠跨语言匹配的问题（中文问、英文证据）；
- 问的是本体里没有、但语料里出现过的说法。

## 四、结论与后续

1. **召回问题已解决**：19/48 → 30/48 @20，@100 达 91.7%。
2. **向量兜底的价值未被证明**，因为当前问题集无法触发它；这不是实现失败，是**度量对象缺失**。
3. 重排阈值（校准值 0.86）是另一个约束：即使召回改善，跨语言相关证据的重排分仍在 0.13–0.15，远低于阈值。单一阈值分不开「跨语言相关」与「参考文献片段假阳性」，这一点在校准文档里已经记录。

因此下一个动作不是继续调召回，而是**构造一份能度量向量兜底的问题集**：从语料里挑出图不覆盖、但有文字依据的问题，单独测「图拒答时向量能否接住」。

## 五、复现

```bash
export UV_CACHE_DIR=$PWD/.uv-cache
uv run --env-file .env idr recall --variants raw,configured --lexical --top-k 100
uv run --env-file .env idr eval --out data/output/reports/vector-recall-20-eval.json
```

召回报告默认落在 `data/output/reports/recall-<时间戳>.json`（`data/` 不入库）。
