# 抽取评估：脱离图谱与检索，直接看断言

对应 issue #33。抽取评估只做一件事：把一批**冻结的真实证据段**交给现有抽取路径，比对产出与人工标注，给出**断言级召回率与精度**。它不读图谱、不跑检索、不写任何数据。

这解决的是 `docs/extraction-variance.md` 里那个问题：以前「改了提示词有没有变好」只能看检索命中率，而检索分数同时受抽取抽样和检索策略影响，无法归因。现在抽取侧有了独立判据，但**单次运行仍然只是一次抽样**；重复 N 次并报告分布属于 #34，见文末。

## 一、标注集

资产在 `src/rotating/idr_rotating/extraction_annotations.json`，与本体、金标准集同级。

- **21 段证据段，来自 6 篇真实语料**：3 篇中文专利（`c169b3184c37a610`、`ddaef5ea68310f1b`、`66f9a7c0b49899ca`）共 11 段，3 篇英文论文（`742178038a41d5ea`、`1be1ecd65c1482c8`、`4f88106f26629c63`）共 10 段。
- 证据段原文与 ID 直接取自已入库图谱（`Evidence` 节点），**没有重新解析 PDF**。ID 形如 `ev:<16 位文献标识>:<页>:<字符区间>`，加载时会校验页、文本长度与字符区间一致。
- 覆盖六种实体类型（`equipment_class`、`component`、`fault_mode`、`fault_cause`、`symptom`、`detection_method`）与五种主要关系（`has_component`、`has_fault_mode`、`has_cause`、`indicated_by`、`detected_by`）。`confused_with` 未被覆盖：语料里没有足够明确的「两种故障易混淆」陈述，硬标会变成编造。

格式：

```json
{
  "schema_version": 1,
  "segments": [
    {"id": "ev:c169b3184c37a610:3:1374-1434", "page": 3, "text": "..."}
  ],
  "expected_entities": [
    {"evidence_id": "ev:c169b3184c37a610:3:1374-1434", "name": "断齿", "type": "fault_mode"}
  ],
  "expected_relations": [
    {"evidence_id": "ev:c169b3184c37a610:3:1374-1434",
     "head": "齿轮副", "type": "has_fault_mode", "tail": "断齿"}
  ]
}
```

加载期会失败的情况（`load_annotations`）：

- 引用不存在的证据段；
- 未知实体/关系类型、内部类型（如 `evidence`）；
- 标注写成别名而不是规范名（流水线会把别名归一成规范名，写成别名必然错分）；
- 关系端点没有在同一段里标注为实体、或违反本体的 domain/range；
- 证据段文本长度与字符区间不符、段落没有任何期望断言、同段重复断言。

## 二、判定规则

评分按**文献**分组：抽取本来就是逐篇调用模型，跨文献的同名概念不能互相顶替。每篇内，期望断言与输出断言先按规范化名称去重（`normalize_term`：全半角、大小写、空白），然后：

| 情况 | 计数 |
|---|---|
| 期望 `(name, type)` 出现在输出 | 命中（召回分子） |
| 输出断言与标注完全一致 | 命中（精度分子） |
| 期望实体没出现、也没有同名实体 | 漏抽 |
| 同名实体出现但类型不同 | 类型不符 |
| 期望关系没出现，但存在同类型且头端或尾端相同的输出 | 端点不符 |
| 期望关系完全没出现 | 漏抽 |
| 输出里有、标注里没有的断言 | 精度损失（分母增加） |

- **召回率** = 命中数 / 去重后的期望断言数。
- **精度** = 命中数 / 去重后的输出断言数。
- 三类未命中（漏抽、类型不符、端点不符）分开计数，互斥；输出多出的断言另算精度损失，可与未命中同时发生。

关系类型不符在实际抽取路径上大多会被本体校验拦下（进待审队列），因此计数通常为 0；判定逻辑仍保留，未来本体允许多个关系共用同组 domain/range 时即可生效。

## 三、命令

```bash
export UV_CACHE_DIR=$PWD/.uv-cache
set -a; . .env; set +a
uv run idr extract-eval --out data/output/reports/extract-eval.json
```

- `--annotations PATH` 换一份标注集；
- `--limit N` 只评按标注顺序的前 N 篇文献，控制真实调用成本；
- `--out PATH` 落盘 JSON（含逐断言状态与输出多出的断言）。

## 四、基线（2026-11-13，单次运行）

模型 `deepseek-v4.1-flash`，6 篇文献、21 段证据段。**这是一次抽样，不是能力估计。**

| 指标 | 数值 |
|---|---|
| 期望断言（同文献内去重后） | 159（实体 98、关系 61） |
| 输出断言 | 91（实体 49、关系 42） |
| 命中 | 20（实体 17、关系 3） |
| **断言级召回率** | **12.6%** |
| **断言级精度** | **22.0%** |
| 漏抽 | 实体 80、关系 48 |
| 类型不符 | 实体 1、关系 0 |
| 端点不符 | 关系 10 |
| 精度损失 | 实体 32、关系 39 |

分文献：

| 文献 | 期望 | 输出 | 命中 | 召回 | 精度 |
|---|---:|---:|---:|---:|---:|
| `c169b3184c37a610`（中文专利，齿轮） | 28 | 10 | 10 | 35.7% | 100.0% |
| `ddaef5ea68310f1b`（中文专利，轴承/转子） | 36 | 34 | 3 | 8.3% | 8.8% |
| `66f9a7c0b49899ca`（中文专利，基础松动） | 30 | 18 | 4 | 13.3% | 22.2% |
| `742178038a41d5ea`（英文，热不平衡） | 28 | 17 | 1 | 3.6% | 5.9% |
| `1be1ecd65c1482c8`（英文，齿轮箱） | 26 | 7 | 1 | 3.8% | 14.3% |
| `4f88106f26629c63`（英文，双栏断齿） | 11 | 5 | 1 | 9.1% | 20.0% |

同一批 `c169b3184c37a610` 的四段证据段，在 `--limit 1` 的一次单独运行里输出 12 条断言、10 条命中，精度 83.3%；全量运行里同一篇输出 10 条、全部命中。**同一输入、同一代码，两次调用的多出断言不同**——这正是 #34 要摊开的东西，单点数字不要当成能力。

## 五、这份标注集最弱的地方

1. **英文文献的命名口径**。抽取输出会做本体归一（`ball bearing` → 滚动轴承、`chipped tooth` → 断齿、`thermal unbalance` → 转子不平衡、`synchronous amplitude` → 1×转频振动突出），而标注按英文原文术语写的是自由词。这部分在评分里同时表现为「漏抽」与「精度损失」，主要压低了三篇英文文献的分数，不全是抽取能力问题。下一步要么给期望断言加「可接受的规范名」一栏，要么英文文献直接按本体规范名标注。
2. **泛化自由词很少被抽出**。`振动信号`、`齿轮故障`、`加速度传感器`、`测振传感器` 这类没有本体实例的概念，模型基本不产出；它们拉低召回，是提示词与本体引导方向的真实反映，但也说明这份标注对「原文术语」的要求比流水线当前契约更严。
3. **同一篇内跨段的端点不符**。评分按文献聚合，`齿轮副 -[has_fault_mode]-> 齿轮故障` 会被判成对另一段产出的 `齿轮副 -[has_fault_mode]-> 齿面磨粒磨损` 的端点不符。断言本身没被抽到是确定的，但「端点不符」这个归因在跨段时并不精确。
4. **`66f9a7c0b49899ca` 的第 2 段（`1:1327-1653`）过密**。一段里标了 14 个实体、6 条关系；其中「轴弯曲 / 不对中 / 共振 / 不平衡」在专利里是「故障原因」，但本体把这些建模成 `fault_mode`，而 `has_cause` 只允许 `fault_mode -> fault_cause`，所以四条「原因是 X」无法表达，只能标注 `indicated_by` / `detected_by`。这暴露的是本体建模缺口，不是标注笔误。
5. **双栏英文版面**。`4f88106f26629c63` 的段落被 PDF 解析切成两栏交错的碎片，部分实体只在半句里出现；保留它是有意覆盖「真实版面质量差」的情况，但期望断言因此偏保守。

## 六、#34 接在哪里

本模块把「跑一次」与「判定」拆开了：

- `extract_annotated()` 返回一篇文献一次的 `ValidatedExtraction`（每篇一次模型调用）；
- `score_extractions()` 是纯函数，输入标注集与逐篇输出，返回 `ExtractionScore`；
- `evaluate_extraction()` 只是两者串联。

#34 在 `extract_annotated()` 外面重复 N 次、每次把结果交给 `score_extractions()`，再复用 `variance.py` 的「分布 + 两两重合度 + 极差」表达即可，不需要改评分本身。命令行层只需要把现在的单份报告扩成多份运行报告。
