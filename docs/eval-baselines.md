# 评估基线：两套评估、两组数字、一条比较规则

对应 issue #35（父规格 #30）。这一页是评估数字的入口：现在两套评估各自的基线是多少、
每个数字到底度量什么、哪些数字能放在一起比。格式、实现与失败分析的细节在文末各专页，
不必先读它们。

**写于 2026-11-13。** 检索与抽取的数字是现场跑命令得到的；旧 50 题基线对着当时留档的
报告核对（它已经无法重跑，原因见第四节）；图谱与标注集版本直接取自提交的文件。

## 一、一句话

- **检索评估**量的是：图谱固定时，问句 → 检索 → 引用组装这一段的正确性。
- **抽取评估**量的是：证据段固定时，模型抽出的断言与人工标注差多少、稳不稳。
- 两套评估互不覆盖：检索分高不能说明抽取好，抽取召回低也不能说明检索差。
- **任何单个数字都不是能力估计。** 判断一个改动有没有效果，要比两条分布，不能比两个数。

## 三、两套评估各能回答、不能回答什么

### 检索评估能回答

- 改了检索、遍历、排序、引用组装之后，**固定图谱上**三项指标有没有变化；
- 逐题差异与失败类型：缺概念、期望证据未命中、缺文献、引用校验失败、证据结构不可达；
- 快照与金标准集是否对得上（校验和绑定），期望证据在冻结图上是否可达；
- 结果是否可重复（同一快照两次运行的 `result_digest` 相同）。

### 检索评估不能回答

- **抽取质量与稳定性。** 图是冻住的，抽取再差也不会反映在这张试卷上。
- 向量召回质量与兜底阈值（快照不含嵌入与 pgvector）。
- 闭包之外的问题（要重新导出快照）。
- 快照里的证据正文是否忠实于 PDF（除非显式传 `--corpus-dir`，且那是另一个数）。
- 本体或提示词改动的效果（快照不重新抽取，改动在下次导出前不可见）。

### 抽取评估能回答

- 同一标注口径下，两次抽取的产出分布有没有分开（命中哪些断言、多抽多少）；
- 改提示词/分批/本体引导后，召回与精度的分布怎么移动；
- 产出稳不稳：两两 Jaccard、每次/至少一次/部分命中的断言数、极差。

### 抽取评估不能回答

- **检索与回答质量。** 它不跑检索，不知道抽出的断言能不能被找到、能不能进答案。
- 绝对抽取能力。标注口径本身有系统偏差（见第五节），当前召回率不能用来说「模型只有
  12%–16% 的能力」，更不能拿它当优化目标。
- 改动是否让用户看到的答案更好——那要端到端评估，本项目暂时没有。

## 四、旧 50 题基线（历史对照，保留可见）

旧基线是在**实时 Neo4j 图谱**上跑出来的抽样。保留它是因为历史数字不能凭空消失，也是
为了说明口径变了多少。**不要把它和快照基线逐项对比后下结论。**

| 指标 | 旧 50 题基线（实时图） | 当前快照基线 |
|---|---|---|
| 检索命中率 | 37/48 = 77.1% | 37/48 = 77.1% |
| ├ 事实型 | 20/24 = 83.3% | 20/24 = 83.3% |
| ├ 对比型 | 9/12 = 75.0% | 9/12 = 75.0% |
| └ 跨文献型 | 8/12 = 66.7% | 8/12 = 66.7% |
| 引用 | 845/845 = 100%（回源 PDF） | 843/843 = 100%（快照文本自洽；PDF 未测） |
| 拒答正确率 | 48/50 = 96.0% | 47/50 = 94.0% |
| 路径分布 | 图 45 / 拒答 4 / 向量 1 | 图 45 / 拒答 5 / 向量 0 |
| 报告 | `data/output/reports/evidence-metric-eval.json`（2026-11-12 21:23 UTC） | 同一命令随时重跑 |

数字接近是巧合，测量条件几乎每一项都不同：

1. **图不同。** 旧基线跑在实时图上，而 M2 期间至少全量重抽过一次语料（见
   `docs/extraction-variance.md`）。`docs/m2-baseline.md` 的运行条件记录的是更早那次基线
   的 67 个概念 / 180 条边；证据口径那一代跑在其后，报告里没有图身份。现在线上图是
   78 个概念 / 179 条边，快照是提交进版本库的一份评分闭包（61 / 165，其 61 个概念与
   158 段证据都能在线上图中找到）。它们不是同一张图。
2. **旧基线依赖向量兜底。** 1 道题走了嵌入 + 重排，分数还依赖外部服务；快照评估只注入
   图读端口，`ask` 保持「图路径失败即拒答」，向量兜底不存在。
3. **引用不是同一个度量。** 旧基线是「回源 PDF、在所标页逐字找到」；快照基线是「引文是
   快照证据原文的逐字片段、文献与页码对得上」。后者能抓凭空造句和挂错证据段，抓不住
   快照正文与 PDF 不一致。
4. **可重复性不同。** 旧基线是抽样：图会被下一次重抽改写，同一条命令重跑得到的是另一张
   图的分数。快照基线是确定的：同一份文件两次运行结果相同。
5. **旧报告没有图身份。** 旧报告只有指标与逐题明细，不记录图校验和、节点数或边数，所以
   连「这个分数对应哪张图」都无法从报告本身确认。

### 旧基线其实有两代，别混用

`docs/m2-baseline.md` 里还留着更早的一代（概念 + 证据口径，2026-11-12 01:00 UTC）：检索
命中 37/48，但按题型是 24/24、2/12、11/12，引用 694/694，拒答 46/50 = 92%。那一代把
「期望概念全部出现」也算进命中，而期望概念是某一次抽取的产物，抽取一抖分数就抖；后来
改成只看证据。两代的分母都是 48，但命中定义不同，**两代之间也不能比**。第四节第一张表
用的是证据口径那一代，因为它的命中定义与当前快照基线相同。

### 旧数字能复核吗

不能。`idr eval --live-graph` 这条路径还在，但它读的是**现在**的线上图（78 / 179），不是
产生旧基线的那张图。重跑得到的是另一张图的分数，与历史数字无关。旧基线只能作为记录
存在，`docs/m2-baseline.md` 保留了当时的运行条件与失败分析。

## 五、抽取基线的口径 caveat：现在不要优化 12%–16%

抽取评估的标注混合了**本体规范名**与**原文自由词**，而流水线会把自由词归一到本体规范名。
英文文献这一点最严重：标注按英文原文写（`ball bearing`、`thermal unbalance`、`phase`…），
模型输出的是中文规范名（滚动轴承、转子不平衡……），**同名不同写法，逐条都判不中**。

实测（两批共 6 次运行）：

| 项 | 数值 |
|---|---|
| 英文文献的期望断言（去重后） | 65/159 = 40.9% |
| 英文文献 6 次运行的命中 | 每次 3/65 = **4.6%**，且每次都是同 3 条 |
| 这 3 条是什么 | 齿轮箱 ×2、转子——都是**中文规范名**，不是英文自由词 |
| 英文文献去重后的期望实体 | 41 条，其中只有 3 条是本体规范名，38 条是英文自由词 |
| 中文文献的命中 | 记录批 22/22/21（23.4/23.4/22.3%），复跑批 18/23/29（19.1/24.5/30.9%） |
| 期望实体的规范名占比 | 原始 129 条里 33 条；去重后 98 条里 21 条 |

那 3 条命中在 6 次运行里一次都没变过——这本身就是「量到的是标注口径，不是抽样」的证据。
结论：英文文献的 4.6% 不是「抽取能力只有 4.6%」，而是**标注口径与流水线归一规则不匹配**。
当前 12%–16% 的总召回率里混着这一块系统性漏计；在标注口径修好之前，**不要把 12%–16%
当作抽取能力的估计，也不要针对它调提示词**——调高了可能只是让模型多吐自由词，不是真的
抽得更准。

修法二选一（都属于后续改动，不在本票范围）：

1. 英文文献直接按本体规范名标注；
2. 给期望断言增加「可接受的规范名」一栏，评分时接受原文词或规范名任一。

在那之前，这份标注集仍然可以用于**相对比较**：同一口径下两批运行的分布变化是有信息量
的；但它给不出绝对水平。

## 六、可比性规则

### 规则

> **一次运行和另一次运行之间不能比数字。** 同一份代码、同一标注集、同一模型，批内 N=3
> 的极差就可能有几个到十几个百分点；跨批次/跨时间的差异通常更大。一个改动只有在**两组
> 分布（每组 N≥3，最好在不同时间各取一组）不重叠**时才算被证明；分布重叠时只能说
> 「没测出差别」，不能说「没有变化」。

具体到操作：

- 抽取评估：同一改动前后各跑一组 `--runs 3`（或更多），比较召回率与精度的区间以及
  `consistent_hits` / `flaky_hits`；不要拿某一批的 #3 和另一批的 #1 比。
- 检索评估：结果是确定的，同一个快照想跑几次跑几次；但**换快照就是换基线**，新快照的
  分数不能和旧快照的分数直接相减（图变了）。
- 任何一次要留档的分数，必须同时记录：资产版本（快照校验和 / 标注集文件哈希）、模型名、
  运行日期、运行次数。

### 这条规则是怎么来的

#34 记录的说法是：跨批次波动（至少 2.5 个百分点召回）大于批内极差（0.6 个百分点）。依据
是 T3 的单次基线 12.6% 与 T4 三次运行 15.1%–15.7% 的差距。那个对照的方向是对的，但
**「批内 0.6 个百分点」只是一批的性质，不是误差上界**：本文复跑批的批内极差是 6.9 个
百分点（召回）、12.3 个百分点（精度），命中集合的 Jaccard 均值也从 0.973 掉到 0.723。

两批之间没有做任何改动，区间却从 [15.1%, 15.7%] 变成 [13.2%, 20.1%]，**重叠**。如果有人
拿复跑批的最好一次（20.1%）去比记录批的最好一次（15.7%），会得出「提高了 4.4 个百分点」
的结论——而实际上什么都没改。这就是本文要求「比分布、不比单点」的原因。

补充两条：

- T3 的单次基线 12.6% / 22.0%（命中 20 条）只有文档记录，报告文件没有留档，本文无法
  复核；但它落在目前所有观测的低端，用它做单点对照同样会把抽样噪声当成效果。
- 精度比召回更敏感：分母是输出断言数，多抽十几条就能让精度掉几个百分点。看精度变化时
  要同时看输出断言数，不要只看比率。

### 分数可比性的前提

| 前提 | 检索评估 | 抽取评估 |
|---|---|---|
| 资产版本 | 快照内容校验和 + 金标准绑定的校验和 | 标注集文件 SHA-256（21 段/159 断言） |
| 代码/提示词 | 同一提交 | 同一提交（提示词、本体、解析与分批参数都在内） |
| 模型 | 不调用模型 | 模型名 + 参数必须相同 |
| 运行方式 | `idr eval`（快照路径） | `idr extract-eval --runs N`（N≥3） |
| 可比范围 | 同一快照内任意次运行 | 同一资产版本下的两组分布 |

已知缺口：抽取评估的报告只记录标注集的名称与条目数，不记录内容校验和或提示词指纹。
跨时间比较时要用 `sha256sum src/rotating/idr_rotating/extraction_annotations.json` 自行
记录版本；补进报告属于后续改动。

### 换资产就要重定基线

- **重新导出快照**（改了图、重抽了语料、补了本体）：旧快照的数字作废，不能和新快照相减。
  导出后要同步更新 `golden_questions.json` 的 `snapshot.checksum`，再跑
  `src/rotating/tests/test_golden_snapshot_binding.py`。
- **改了标注集**（补标注、改规范名）：旧标注集的召回/精度不可比；应记录新的文件哈希，
  并把它当作新基线。
- **改了本体或提示词**：抽取评估要重跑（分布对比）；检索评估在快照重新导出之前完全看不到
  这个改动，不要用「检索分没变」证明本体改动没影响。

## 七、决策速查

| 你改了什么 | 看哪套 | 怎么判 |
|---|---|---|
| 检索、遍历、排序、引用组装 | 检索评估 | 固定快照上三项指标 + 逐题 diff；两次运行 `result_digest` 相同说明改动本身是确定的 |
| 抽取提示词、分批、本体引导 | 抽取评估 | 同一资产版本下两组 N≥3 的分布不重叠；否则记为「没测出差别」 |
| 本体类型/关系定义 | 两套都要，但不能直接比 | 抽取侧重跑分布；检索侧等快照重新导出后重记基线 |
| 语料、切分规则 | 抽取评估 + 重新导出快照 | 旧快照与旧标注都可能作废，新基线从零记 |
| 想回答「系统现在有多好」 | 都不够 | 检索分是「固定图上的条件分」，抽取召回受标注口径污染；没有端到端评估前不要给绝对结论 |
