# 图谱采用「概念 + 证据」双层节点，本体锚定行业标准

图谱同时容纳两类节点：**概念节点**（部件、故障模式、征兆、疾病、症状、检查…）承载可推理的领域知识；**证据节点**（文献原文段落）承载出处。概念节点通过指向证据节点的边连接原文，答案中的每条结论都必须能沿该边回溯到具体段落。

只建概念图无法回答验收时的第一个问题「依据是哪篇、哪段」；反过来，把每条 claim 都拆成节点，在本期每领域 100–300 篇的语料规模下，抽取成本与噪声远高于它带来的推理收益。

本体不靠 LLM 自由归纳，而是锚定既有体系。设备领域的故障模式词表来自 **ISO 15243:2017**（滚动轴承，六类损伤机理）、**ISO 10825-1:2022**（齿轮齿面损伤）、**IEC TS 60034-24:2009**（电机电气故障）；转子与结构类找不到任何标准分类，自建并标注 `source: 自建`。医学领域用 ICD-10 与 SNOMED 的术语体系。LLM 在受控类型清单内抽取，清单外的新类型进入待审队列而非直接入库。没有标准锚定的本体必然发散成幻觉集合，既无法评估也无法交付。

## 故障模式的建模维度

标准分类按**损伤机理**划分（疲劳、磨损、腐蚀…），不区分**位置**；而位置恰恰决定特征频率——外圈剥落对应 BPFO，内圈剥落对应 BPFI，这是诊断的立足点。严格照抄标准会让图谱分不出外圈与内圈。

因此故障模式按「位置 × 损伤形式」建模：`location` 决定特征频率，`damage_form` 对齐标准术语，只列文献中真实出现过的组合，不做笛卡尔展开。`external_code` 保留标准条款号以便追溯。

## 许可证边界

ISO 标准是付费版权文本，**不复制其表格结构与描述文本**，只借用术语与条款号，分类结构由本项目自行组织。

## 修订记录

- **2026-11-10 更正锚定标准。** 初稿写作「设备领域用 ISO 10816 / ISO 13373 的振动评定与故障模式分类」，经核查该表述有两处错误：ISO 10816-1 已于 2016 年被 ISO 20816-1 取代（现行版 ISO 20816-1:2026）；且 ISO 20816 只规定振动测量与评定，ISO 13373-3 是诊断流程，**两者都不包含故障模式分类**。词表改锚 ISO 15243 / ISO 10825-1 / IEC TS 60034-24。
- **2026-11-10 增加建模维度。** 补充「位置 × 损伤形式」一节，说明为何不能直接照抄标准分类。
- **2026-11-11 概念层跨文献合并（issue #10）。** 概念节点身份改为：命中本体规范实例时用共享 ID `concept:{实例 ID}`，节点**不带** `doc_id`，因此同一概念在多篇文献里只留一个节点；未命中规范实例的自由词保留 `{doc_id}:concept:{key}`，限定在文献内。所有边（概念→概念、概念→证据）都带 `doc_id`，同一概念对在不同文献里各留一条并行边；写入一篇文献前先按 `doc_id` 删除它上次贡献的节点与边，共享概念节点不受影响。`evidence` 实体类型与 `evidenced_by` 关系类型是证据层的内部结构，在本体中标记 `internal: true`，不进入抽取提示词，模型输出也拒入待审队列。

- **2026-11-12 引用锚点（issue #22 / 票据 #23）。** 每条断言的出处从「证据段」细化为「证据段 + 段内字符区间」：模型给出支撑原文片段，入库前校验它必须在所引证据段里逐字出现，通过后固化为锚点 `(evidence_id, start, end)`，与 `evidence_ids` 平行挂在 `Provenance` 上，两类边共用。图里用 `anchor_evidence_ids` / `anchor_starts` / `anchor_ends` / `anchor_ambiguous` 四个平行数组属性表达（Neo4j 属性不支持嵌套映射）；没有锚点的证据段仍可按整段引用。片段出现多次时取首次并标记歧义；片段对不上或模型没给的断言进待审队列（`anchor_not_found`），不写图。切分规则与证据段 id 完全不变——锚点叠在证据段之上；锚点定位规则参与抽取指纹（抽取契约版本升到 3），所以已有文献需要重抽取才会产生锚点。

- **2026-11-12 引用改用锚点（issue #22 / 票据 #24）。** 答案层不再只按证据段组织引用：图检索把边上的锚点读进 `FactEdge` / `AggregatedFact` / `PathStep`，引用层按「证据段 + 锚点」展开，`Citation.text` 是锚点区间对应的原文、`Citation.anchor` 记录区间，同一证据段支撑多条断言时每条断言各有一条引用；没有锚点（锚点上线前的旧边或模型没给片段）时退回整段，行为与锚点上线前一致。页码与证据段标识不变，引用准确率口径仍是「回源 PDF、所标页逐字比对」，校验器不需要理解锚点。

- **2026-11-12 无锚点选句兜底（issue #22 / 票据 #25）。** 没有锚点的旧边不再一律整段引用：查询期按断言的头概念名、关系标签与尾概念名对证据段逐句做词法重合打分，取覆盖命中最多的连续句子窗口作为引用区间。选句只在句子边界上取整句，`text[start:end]` 仍是证据段原文的连续切片，回源逐字校验口径不变；选句只影响引用展示，检索命中的判定单位仍是整条证据段。头、尾概念名都没有命中时退回整段，不凭「表现为」这类通用关系词选句。

- **2026-11-12 短锚点展示上下文（issue #22 / 票据 #26）。** 公式区被版面切分成 9–52 字的碎片时，锚点本身可读性很差。引用层因此把短于 60 字的**入库固化锚点**的展示文本并入同页相邻证据段：合并在页面文字坐标系里进行，只并入同一页、连续（间隔 0 个字符或 1 个换行，后者是文字层连接行的方式）的证据段，展示文本上限 240 字；锚点区间本身不变，`Citation.text` 因此可能比锚点区间宽。展示文本始终是页面文字的连续切片，回源逐字校验的口径与校验器都不变。查询期选句（#25）得到的窗口已落在句子边界上，不再二次并入上下文。为支持合并，图谱读模型 `EvidenceRecord` 增加 `charspan`，读端口新增 `evidence_by_page`（同页证据段按字符区间升序）。

## Consequences

- 抽取结果必须通过本体校验才能入库，校验失败是**数据错误**而不是警告。
- 金标准集的每一条都必须挂到证据节点上，否则该条不可用于评估引用准确率。
