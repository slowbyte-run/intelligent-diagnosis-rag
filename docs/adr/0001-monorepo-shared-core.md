# 单仓库 + 共享核心 + 两个领域包

旋转设备故障诊断与肺部疾病诊断的 RAG 流水线同形（解析、抽取、图存储、检索原语、生成、评估），但领域知识完全不同。我们采用一个 uv workspace 单仓库：`src/core` 只承载与领域无关的流水线代码，`src/rotating/` 与 `src/pulmonary/` 各是一个领域包，两者只依赖 core、互不依赖。第二个领域等第一个跑通并通过评估基线后再启动，届时才把被证实的共享逻辑下沉到 core。

选择单仓库而不是两个独立仓库，是因为两边共享的是同一套代码，分仓意味着一份 bug 要修两遍；拒绝一开始就把 core 做厚，是因为真正稳定的共享边界只有在两条链路都跑通之后才看得见，提前抽象只能得到猜出来的接口。

## Consequences

- 领域包之间禁止互相 import，由 `AGENTS.md` 的架构约束条款强制。
- 若某天两个领域确实分道扬镳，任一领域包可以整体迁出为独立仓库，因为它只依赖 core。
