# 向量兜底阈值校准

`vector_min_rerank_score` 是「向量兜底有没有依据」的判据，也是拒答判定的最后一
道闸门。它是猜出来的初值，必须用金标准集校准后才能作为度量依据（#17）。本文
记录校准口径、操作方法、当前结果与已知局限；**数值的事实源是
`src/rotating/config/retrieval.yaml`**，本文只解释它为什么是这个数。

## 一、拒答判据与两种原因

一次提问走图路径优先的检索：

1. 图路径沿白名单关系取到带证据的事实 → 回答，不看阈值；
2. 图路径没有依据 → 向量召回 + 重排，最高分低于阈值 → 不答题；
3. 两条路都没有依据 → 拒答。

拒答必须说明原因（`Answer.refusal_reason`，JSON 字段 `refusal_reason`）：

| 原因 | 含义 | 用户该做什么 |
|---|---|---|
| `no_concept` | 问题里没有任何片段链接到本体概念 | 换个问法，或维护者补别名 |
| `no_evidence` | 概念识别了，但图没有带证据的事实，向量兜底也没有候选过阈值 | 补语料，或补概念间关系 |

几个边界情况归入 `no_evidence`，因为概念确实识别了：命中的概念不在白名单关系的
定义域内（如只问「温升异常」）、问句同时命中多个同等具体的概念（歧义）、概念存在
于本体但不在图谱里。歧义问题**不**降级走向量：向量分不清该答哪个概念，兜底只会
把歧义藏进一个像模像样的答案里。

拒答是值对象的不变量，不是调用点的自觉：`Answer` 在构造时拒绝「拒答路径没有
原因」和「拒答带 `facts`/`citations`」两种形态，因此拒答不可能携带推测性结论。

拒答原因**不参与** `idr eval` 的拒答正确率：该指标只判路径是否为拒答（指标定义是
数据模型，改动要单独评审）。原因可以在 `idr ask --json` 的 `refusal_reason`、人类
可读输出与校准报告里核对。

## 二、校准命令

前置条件：Neo4j 与 Postgres 已启动，`.env` 已填（与 `idr ask` / `idr eval` 相同）。

```bash
set -a; . ./.env; set +a
uv run idr calibrate            # 只采样 + 出报告，不改配置
uv run idr calibrate --write    # 再把推荐阈值与校准标记写回配置
```

- **成本**：每题 2 次模型调用（嵌入 + 重排），20 题约 40 次；阈值扫描在内存里对
  同一份分数做，不按阈值重复调用模型。所以一次校准是「一遍采样 + 一次离线扫描」。
- **报告**：默认写 `data/output/reports/calibration-<时间戳>-<随机>.json`
  （gitignored），含全部候选分数、扫描表与选择理由，供复现与对比。
- **写回**：`--write` 只改 `vector_min_rerank_score` 数值与
  `vector_min_rerank_score_calibrated` 标记两行，保留注释与其他键；写回后会按正常
  加载路径复读，解析不过就不落盘。
- `--golden` 可指定别的金标准集；`--config` 可指定别的检索配置；`--out` 指定报告
  路径。线上流程不需要这些参数。

## 三、采样与判分口径

采样时把阈值临时设为 0、结果上限放宽到召回数，保证看到完整的分数分布：

- **可答题**（`expect_refusal=false`）：看金标准绑定的证据段是否仍在阈值之上；
  至少命中一个绑定证据段才算「期望证据保留」。这与 `idr eval` 的检索命中率口径
  一致，但只作用于向量路径。
- **拒答对照**（`expect_refusal=true`）：阈值之上是否还有任何候选；有候选就说明
  向量路径会答题，该拒答对照算错。

**边界只取关键分数**：每道题的最高分（决定「还有没有候选」）和可答题绑定证据段的
分数（决定「期望证据保不保留」）。其余候选分数不改变任何结论，不参与切分——早期
版本把 400 个候选分数全当边界，低分噪声把分数轴切碎，稳定余量永远凑不满。

## 四、选点规则

1. **硬约束**：阈值必须高于每一道拒答对照的最高分，保证「该拒尽拒」；
2. **稳定性**：阈值离最近的关键分数至少 `0.02`。重排服务是生成式模型，同一对
   「查询—证据」重复打分约有 `0.01` 抖动，取两倍作为稳定余量；
3. 在满足前两条的点里，先选期望证据保留最多，再选离关键分数最远，最后取更低阈值；
4. 做不到就写明牺牲了哪个目标，并把更优的「更低阈值」及其代价一起打印出来。

「最不坏」的默认方向是**拒答优先**：一条编造或错位的证据比一次明确的「答不了」
更伤害可核对性（AGENTS.md 第 6 条）。因此算法不会为了多保留一条证据而把阈值压到
拒答边界上。

## 五、本次校准（2026-11-12）

金标准 20 题（可答 18、拒答对照 2）。分数分布：

| 组 | 观测 |
|---|---|
| 可答题最高重排分 | 0.0509（X-04）– 0.9929（F-03），中位数 0.9239 |
| 拒答对照最高分 | R-02 `no_concept` 0.0017；R-01 `no_evidence` 0.6965 |
| 绑定证据进入 top-20 的可答题 | 6/18：F-03 0.9929/0.9794、F-07 0.6009、F-08 0.7342/0.3190、P-02 0.1332、P-03 0.9813、X-01 0.1507 |

R-01（汽轮机，语料里没有该设备的内容）在阈值 0.35 时被答题，引用的是三条**参考
文献列表/表格标题片段**（0.6965、0.6179、0.4806），不是正文结论——这是「引用准确
但语义错位」的典型。

选点过程：硬约束给出 `> 0.6965`。其上的关键分数依次是 0.7342（F-08 的绑定证据）
与 0.8327（F-06 的最高分）：

- `(0.6965, 0.7342]`：中点数 0.72 能保留 F-08 的证据（3/18），但离两侧只有
  `0.019`，低于稳定余量；
- `(0.7342, 0.8327]`：中点 0.783，离两侧 `0.046`，稳定；期望证据 2/18。

**校准值：0.78**（写入 `retrieval.yaml`，`vector_min_rerank_score_calibrated: true`）。
阈值之上：拒答对照 2/2 拒答、期望证据 2/18（F-03、P-03）、15/18 可答题仍有候选
可答。0.72 的备选被明确记录为「能多保留一条证据，但贴着拒答边界」，不采用。

## 六、为什么没有「更好的单一阈值」

这是本次校准最重要的结论：**不存在一个阈值能同时拒掉 R-01 又保留跨语言证据。**

- 跨语言相关证据实测可低至 0.1332（P-02）、0.1507（X-01）；
- R-01 的假阳性在 0.4806–0.6965；
- 两者与「无关但分数很高」的候选区间重叠：可答题最高分中位数 0.9239，而 12/18
  的可答题连绑定证据都没有被 top-20 召回。

所以「把阈值降到能接住 0.13–0.15」= 把 R-01 一起放进来（拒答正确率从 90% 掉回
85%），而且换不来检索命中：低阈值下期望证据最多也只有 6/18，其余题目是召回本身
没找到绑定证据，阈值救不了。当前取**保守侧**：0.78，宁可拒答，也不拿参考文献
片段当依据。

代价是明确的：重排分 0.35–0.78 的候选不再进答案。对当前金标准集，这些题都由图
路径回答，所以三项指标没有因此变差；对未来的「图路径失败 + 跨语言证据」的问题，
向量兜底会拒答。

## 七、校准揭示的、指标看不见的东西

- **引用准确率 100% 不等于引用相关**：它只校验引用能在所标页逐字找到。R-01 的三
  条引用全部逐字命中，内容却是参考文献列表；修复前它把「拒答正确率」拉低，却让
  引用准确率看起来完美。
- **检索命中率 77.8% 几乎全部由图上贡献**：16/18 的命中走图路径，向量路径在
  「可答题」上一条命中都没有（校准时强制走向量也只有 2/18 保留绑定证据）。这个
  数字掩盖了向量兜底的真实召回能力。
- **拒答正确率的分辨率只有 5 个百分点**：20 题里只有 2 道拒答对照，一道题就是
  5pp。本次 85% → 90% 只是「R-01 从答错变成拒答」，不足以支撑更细的阈值比较。
- **重排分数不可重复**：同一题同一候选在两次采样中相差约 0.01（R-01 0.6965 与
  0.6923）；贴着边界的阈值（如 0.72）存在真实的翻面风险。
- **对比型题（P-01/P-02）的拒答与阈值无关**：它们因为同时命中两个同等具体的概念
  而拒绝兜底。这是实体链接的歧义问题，不在 #17 的范围内。

## 八、提议但未实现的方向

以下只作为后续提案，不在 #17 落地（改动检索策略前应先有评估基线）：

1. **查询翻译 / 跨语言重排指令**：把问题翻译成证据语言后再重排，或给重排服务显式
   的跨语言指令，使同义跨语言对回到可比区间；之后重新校准。
2. **按语言或按拒答原因分阈值**：数据不支持简单二分——R-01 是 `no_evidence`，与
   跨语言可答题同属一类，无法只靠原因区分。若要做，必须先用更多拒答对照和跨语言
   正例证明两组分布可分。
3. **混合召回**：向量召回漏掉了 12/18 的绑定证据，这是比阈值更大的瓶颈。BM25/
   关键词召回已在 spec 里明确延后，不在本票处理。

## 九、什么时候要重新校准

- 语料、图谱或金标准集变化（M2 期间语料与图谱冻结，证据段 ID 才不会失效）；
- 更换嵌入或重排模型（分数尺度会变，旧阈值没有意义）；
- 拒答对照或可答题的分布明显变化（例如新增大量跨语言问题）；
- `idr eval` 的拒答正确率或检索命中率出现无法用代码变更解释的漂移。

流程：`idr calibrate` 看推荐值与代价 → `idr calibrate --write` → `idr eval` 对比
三项指标 → 更新 `retrieval.yaml` 的注释与本文「本次校准」一节 → 一起提交。只写
数值、不写理由的阈值改动视为未校准。
